## Decision and scope

The [G0 database-lineage evidence](2026-08-31-g0-baseline.md#rerun-db-legacy-01--database-lineage)
records a read-only inspection of the deployed `health` database. Its seven
enum types already have canonical lowercase labels. The database is
unversioned; absence of migration metadata does not prove an uppercase legacy
schema. No corrective enum migration is needed for that observed target.

Remove `backend/drizzle/0005_enum_value_alignment.sql` from the startup patch
directory. Keep `0000`, patches `0001`–`0004`, and the upstream
`0006_site_settings.sql` unchanged. The migrator discovers SQL files from
disk on every run; it does not require consecutive migration numbers or a
journal entry for the removed patch. No database downgrade or label reversal
is needed for the canonical target. The removed file remains recoverable
from commit `8c508b5`; no Git history was rewritten.

**Compatibility change:** startup no longer converts known legacy uppercase
enum labels or provides the removed patch's mixed-label diagnostic. A
noncanonical database requires its own schema audit and migration before
application startup. This closure does not approve bootstrapping an unknown
schema.
