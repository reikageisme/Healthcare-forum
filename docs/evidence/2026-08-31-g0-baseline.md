### RERUN-POLICY-01 — effective behavior versus approval gate

Current source evidence narrows the decisions but does not replace owner
approval:

1. Feed queries require `is_published=true`, and public feed/detail status is
   constrained to `approved`; however approved-unpublished detail is still
   visible, while comments, reactions and bookmark toggles use the
   existence-only `findPostOr404`. Bookmark listing filters publication but
   not approval status. A unified non-public interaction policy is still open.
2. Newly issued JWTs have `access`/`refresh` kinds and refresh strictly rejects
   untyped tokens. Middleware rejects a refresh token as access but still
   accepts a valid old token with no kind as access until it expires. The exact
   forced-login/compatibility policy is therefore not fully implemented or
   approved.
3. Backend writes use `sanitize-html`; `package.json` requests `^2.13.1` and
   the installed version is 2.17.7, but no lockfile pins it. The current
   allowlist includes broad rich-text/table tags, selected inline styles,
   `http`/`https`/`mailto`, and relative upload URLs. The package version,
   exact TipTap allowlist and legacy backfill acceptance remain unapproved.
4. No `.github` workflow or PostgreSQL CI gate exists, so per-merge versus
   integration/nightly policy remains undecided.
5. Production startup validates JWT-secret length, but does not yet fail fast
   for every missing/unsafe database URL or CORS setting.

T0.3 / POLICY-01 remains **pending owner approval**.

implemented:
